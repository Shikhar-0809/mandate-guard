# EVAL

The measurement protocol is the submission's spine. Track 02's bar is a
measurement bar, not an architecture bar.

## Corpora

**A — benign base traffic.** Synthesised. Every distributional parameter lives in
`data/GENERATION.md` as a config value with a citation or the word `ASSUMPTION`.

**B — hard negatives.** Legitimate-but-suspicious. Target ≥ 15% of the negative
class. Archetypes derived from citable sources (chargeback reason codes, NPCI
mandate circulars, published merchant substitution policies), not imagination.

Archetypes: stockout substitution · in-tolerance price drift · partial capture ·
retry with fresh idempotency key · legitimate basket split · subscription step-up
with notice · subsidiary name confusability · post-snapshot delivery fee ·
currency rounding · correctly-narrowed sub-agent delegation.

**C — attacks.** Stratified by cause and by strategy family.

## Splits

Split on **strategy family**, not samples. Dev sees families 1–7; the sealed set
holds 8–12. Report `recall_seen` and `recall_unseen` separately.
**`recall_unseen` is the headline number.**

Dev attacks generated by one model family; sealed-set attacks by a different
family plus hand-authored samples. Temporal split layered on top.

Base rate: stated prior (~0.8%), never 50/50. Report precision at that prior
plus a precision-vs-prevalence curve.

## Sealed set

SHA-256 committed to the repo before development; git history proves when.
Touched only by `make seal-eval`, which increments `evaluated_count`.
That count ships in the README.

Never inspect, plot, or tune on the sealed set.

## Leakage gates — in `make check` from the first feature onward

- Shuffled-label AUC must land in [0.45, 0.55]
- Generator-provenance probe AUC must be < 0.60
- FP rate on Corpus B must exceed Corpus A by a stated margin, or the hard
  negatives are not hard

## Baselines to beat

allow-everything · block-everything · amount-threshold · **regex injection
detector** · T0 rules only

Beating the regex detector is the empirical justification for the entire
mandate-deviation framing.

## Operating point

```
τ* = argmin_τ [ FP(τ)·₹320 + FN(τ)·₹1470 + HOLD(τ)·₹45 ]
```

Not F1. F1 assumes FP and FN cost the same; here they differ by 4.6×.
Show the curve for two tenant profiles with two different optimal points.

## T2 KILL CRITERION

**Pre-registered 2026-08-27, before any T2 code exists.**

If T2 does not lift `recall_unseen_families` by ≥ 2 percentage points over
T0+T1 on the dev set, T2 ships wired, documented, and degraded by default.
It is then presented as an architecture decision, not a metrics win.

This criterion was written before the result was known and is not revised after
seeing it.
